# 📱 Mandal Admin App — v0.0.3

Android admin app for Bageshwar Bala Ji Sundarkand Mandal, built with
[Capacitor](https://capacitorjs.com) (a thin native Android shell around a
mobile web app). Full background and reasoning: [`../guide.md`](../guide.md), Phase 3.

## What it does (v0.0.3)

Same feature set as the web admin panel, reused directly — login-protected,
talks to **Firestore directly** (not through `backend/` — see
"Architecture" below), with **full Add/Edit/Delete** on every section:

- 🔐 Login (Firebase Auth, single admin account)
- 📊 Dashboard stats (pending donations, total verified, events, members)
- 📅 Event management — add/edit/delete, **including the new optional
  Expiry Date field** (multi-day events can stay listed past their start date)
- 🙏 Donation verification (approve / edit / delete)
- 🎬 Past live recordings (add/edit/delete YouTube links)
- 🖼️ Gallery upload (straight to Cloudinary, same as the website) with
  caption editing and optional image replacement
- 👥 Member management (add/edit/delete, with photo upload/replacement)
- 📖 Sundarkand verse management (add/edit/delete)
- ⚙️ Settings — announcement bar text, current live YouTube link
- 🎨 Real app icon + splash screen (generated from the Mandal logo) and a
  themed loading screen while Firebase confirms login state

## Architecture

The app talks to **Firestore directly** via the Firebase JS SDK — the exact
same pattern as `web/js/admin.js`, which this app's code is adapted from.
This was a deliberate security decision (see `guide.md`, Phase 3): it avoids
putting the powerful Firebase Admin Service Account key on any more public
surfaces than the one narrow cleanup job in `backend/` already needs.

```
mobile-app/
├── www/                    ← the actual app UI (HTML/CSS/JS, runs in the WebView)
│   ├── index.html           login screen
│   ├── dashboard.html       main admin dashboard (tabbed)
│   ├── css/style.css        (copied from web/, same visual theme)
│   ├── js/firebase-config.js (copied from web/, same Firebase project)
│   ├── js/admin.js          (adapted from web/js/admin.js — see diffs below)
│   └── assets/logo.webp, default-member.svg
├── android/                 ← native Android project (generated by Capacitor CLI)
├── capacitor.config.json
└── package.json
```

### How `www/js/admin.js` differs from `web/js/admin.js`

- Page detection & redirects use `index.html` / `dashboard.html` (the app's
  file names) instead of `admin-login.html` / `admin-dashboard.html`
- Event form now reads/writes an `expiryDate` field
- Events table now shows the expiry date alongside the event date
- No "← Back to Website" link on login (doesn't make sense inside a
  standalone app)

## Building the APK

Two ways — use whichever fits your mood, per your own preference:

### Option A — GitHub Actions (recommended default, close to zero effort)
Push to `main` with changes under `mobile-app/**`, or trigger manually from
the **Actions** tab → "Build Android APK" → **Run workflow**. Download the
finished `.apk` from the run's **Artifacts** section. Full steps in
`guide.md`, Phase 3.

### Option B — Termux, on-device
```bash
cd mobile-app
npm install
npx cap sync android
cd android
chmod +x gradlew
./gradlew assembleDebug
# APK appears at: android/app/build/outputs/apk/debug/app-debug.apk
```
Full Termux setup (Java/Android SDK packages needed) in `guide.md`, Phase 3.

## Installing on your phone

The debug APK is unsigned by a release key (fine for personal/community use,
not for the Play Store). Transfer `app-debug.apk` to your phone, tap it, and
allow "install from unknown sources" if prompted — first time only.

## Troubleshooting

**"Wrong email or password" but credentials are correct:**
The login screen now shows the *real* Firebase error instead of always
guessing. Try again on the latest build and read the exact message shown.
Most likely cause for a Capacitor app specifically:
`auth/unauthorized-domain` — check Firebase Console → Authentication →
Settings → Authorized domains and confirm `localhost` is listed (Capacitor
serves the app from `https://localhost`).

**App looks "zoomed out" / like a desktop site:**
Fixed the most likely causes (missing status-bar theme colors, viewport
meta hardening). If it persists: check the app isn't running in a
resized floating/split-screen window (a system gesture on some
Samsung/Xiaomi phones), then try remote debugging — connect via USB with
Developer Options → USB debugging on, open `chrome://inspect` on a
computer's Chrome, find the app's WebView, and inspect the actual
rendered viewport width.

## Known limitations (v0.0.3 — by design, will grow gradually)

- Debug build only, not optimized/signed for public distribution
- No offline support — needs an internet connection, same as the website
- Single hardcoded admin account (matches the website's current model)
